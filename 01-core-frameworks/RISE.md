# R-I-S-E：多步驟任務與複雜資料整理

**適合情境**：整理較長逐字稿、清洗問卷，或工作本身有明確先後順序時。

**為什麼這樣寫**：把資料、步驟和輸出要求分開寫，長內容比較好整理，也方便檢查哪一步漏了。

**可能失敗的地方**：步驟太長時，先拆掉不必要步驟；再複雜就分階段處理，或中間加檢查。

---

## Prompt 範本（可直接複製）

```
<role>
你是一位專業的文字清洗與資料結構化編輯。
</role>
<input_data>
[貼上原始文字材料]
</input_data>
<steps>
請嚴格按照以下順序執行，不要跳步：
第一步：過濾材料中的口頭贅字與無意義寒暄。
第二步：抓出每項任務的負責人、截止日期與具體交付物；材料沒說清楚的，統一填「待確認」，不要自行補充。
第三步：整理成 Markdown 表格，欄位：事項 ｜ 負責人 ｜ 截止日 ｜ 交付成果。
</steps>
<expectation>
只輸出最終表格，不需要過程草稿與結尾問候。
</expectation>
```

---

**使用提示**：適合資料整理和流程型工作；只問簡單概念時，沒必要寫這麼完整。
