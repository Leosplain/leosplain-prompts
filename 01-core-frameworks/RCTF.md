# R-C-T-F：商業分析與專案評估

**適合情境**：專案復盤、營運分析或提案草稿，需要把內容整理成固定區塊時。

**為什麼這樣寫**：角色和背景先講清楚，模型比較知道要站在哪個角度；數量和格式也先寫清楚，後面比較好檢查。

**可能失敗的地方**：只寫「分析原因」卻沒要求落地做法，結果容易變成泛泛建議。

---

## Prompt 範本（可直接複製）

```
[Role] 你是一位專注於營運流程優化的資深顧問。
[Context] 我們是一家 20 人的技術團隊，目前日常會議偏多，成員反應專注開發時間被打碎。
[Task]
1. 分析導致會議效率低落的 3 個常見核心原因。
2. 針對每項原因提出 1 個具體的改善規則。
3. 語氣務實，避免純理論說教。
[Format]
- 用 Markdown 表格呈現：問題原因 ｜ 改善規則 ｜ 預期成果
- 表格下方附 100 字以內的總結建議。
```

---

**使用提示**：把 Context 換成你的真實背景，Task 的數量與 Format 依需求調整。簡單問題通常不需要整套。
