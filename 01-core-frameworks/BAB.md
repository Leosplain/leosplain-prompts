# BAB：痛點切入與文案說明

**適合情境**：產品說明、自動化流程或專案成果，要把「原本有什麼問題」和「後來怎麼處理」講清楚。

**為什麼這樣寫**：Before 和 After 先寫清楚，模型比較容易抓到這段內容要解決什麼。

**可能失敗的地方**：痛點只有「很麻煩」「很浪費時間」，結果仍會空泛。

---

## Prompt 範本（可直接複製）

```
請用 BAB 結構為這套新流程寫一段說明：
- [Before] 痛點：每次開完會都要花一兩個小時手動重聽錄音、整理會議記錄，耗時且易漏掉待辦事項。
- [After] 理想狀態：會議結束後，能在短時間內自動整理出清洗後的文字、摘要與待辦表格。
- [Bridge] 解法：使用本機模型處理資料，可以減少資料需要送往第三方雲端服務的情況；實際資料風險仍取決於使用的模型、工具設定，以及是否啟用雲端功能。

寫作限制：
1. 語氣平實務實，不使用誇飾詞。
2. 產出 1 組標題與一段 150 字以內的正文說明。
```

---

**使用提示**：適合產品或專案說明；中立比對、除錯或事實查核時，不會優先用這套。
